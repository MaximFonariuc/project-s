# Project S

Правила разработки живут в одном файле — `AGENTS.md` (общий формат для всех AI-агентов). Читать его до первой правки.

@AGENTS.md

## Карта документации

`AGENTS.md` задаёт правила, но не описывает, где искать факты о конкретной подсистеме. Порядок чтения перед правкой:

1. `Docs/Architecture.md` — текущая архитектурная база: физические границы, владельцы состояния, composition. Отсюда видно, кому принадлежит то, что предстоит менять.
2. `Docs/Architecture/<Feature>.md` — 32 файла по подсистемам (`Combat.*`, `Character.*`, `Player.*`, `Input.Player`, `Core.Assemblies`, `Core.Tests`). Каждый начинается с раздела «Ответственность» и содержит mermaid-диаграмму классов. Читать тот, который относится к задаче, а не весь каталог.
3. `README.md` рядом с кодом — 17 файлов в `Assets/_App/Core/Runtime/**` и в корнях модулей. Описывают границу конкретного дерева классов и то, чего оно не делает.
4. `Assets/_App/Modules/Input/Documentation~` и `Assets/_App/Modules/StateMachine/Documentation~` — class trees, lifecycle и package boundary этих двух модулей.
5. `Docs/AI/UnityProjectContext.md` — сгенерированный инвентарь окружения: версия Unity, пакеты, границы сборок, с колонками Confidence и Evidence. Полезен для быстрой ориентации, но это снимок на дату и коммит из его заголовка — расхождение с текущим кодом решается в пользу кода.

`Docs/Animation` — аудиты качества анимаций и справочник по CharacterAnimationCore, не правила.

## Документация — часть изменения

- Меняется поведение подсистемы — правится её файл в `Docs/Architecture/` и `README.md` затронутого дерева, в той же задаче.
- Стейл-документ правим, а не создаём рядом вторую версию.
- Новый модуль в `_App/Modules` получает `README.md` с границей и направлением зависимостей.
- `Docs/AI/UnityProjectContext.md` руками не правим: он генерируется.

## Коммиты

Conventional Commits, императив с маленькой буквы: `feat|fix|refactor|perf|test|docs|chore(scope): <что сделано>`. Scope — подсистема (`combat`, `character`, `animation`, `traversal`, `enemies`, `architecture`, `tests`, `assemblies`).

Код и документацию к нему коммитим отдельными коммитами в рамках одной задачи: сначала изменение, затем `docs(scope): ...`.

Сообщение — одна строка, без тела и трейлеров.

## Стиль

Машинный источник — корневой `.editorconfig`. Ключевое: явные типы, `sealed` по умолчанию, `internal` пока тип не нужен снаружи, Allman, скобки всегда, block-scoped `namespace`, `using` вне namespace, `Try*` + `out`, `in` для структур, CRLF без завершающей пустой строки. Комментариев в коде нет.
